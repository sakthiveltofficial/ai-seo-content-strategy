> **Adaptation note:** These are starting templates for the Webnox-style AI-native services context. Choose sections, word count, FAQs, schema and CTA based on the real business goal, user intent, observed SERP, evidence available and current search policies; they are not mandatory checklists for every page.

# Page Type Templates

### Template 1: Main Landing Page (Flagship)
Hierarchy:
```
[ HERO SECTION ] — Value-first: What You Get + engineering-aligned CTA
      │
[ PROOF SECTION ] — 'Built for Real Enterprise Workflows' (proof before pitch)
      │
[ CONCEPT DEFINITION ] — 'What Is [Category]?' (featured snippet target)
      │
[ COMPARISON MATRIX ] — Traditional vs AI-Native (no self-brand harm)
      │
[ CORE PILLARS (numbered H2+H3) ] — Primary positioning services (70% weight)
      │
[ SECONDARY FLYWHEEL ] — Supporting services (30% weight, single H2)
      │
[ DELIVERY PROCESS ] — Staged timeline with week numbers
      │
[ OPTIONAL FAQ ] — use only when supported by query/user research; answer-first format
      │
[ ENGINEERING CTA ] — Specific action + subtext
      │
[ STRUCTURED DATA ] — relevant, valid page/entity types; verify current eligibility/policies
      │
[ INTERNAL LINK MAP ] — Table: anchor text → target URL → placement context
```

### Template 2: Forward Deployed Engineering (FDE) / Engagement Model Page
Hierarchy:
```
[ HERO ] — Value-first: What the embedded pod delivers
      │
[ DEFINITION ] — 'What Is [Engagement Model]?'
      │
[ WHY BETTER ] — Comparison table: Traditional Outsourcing vs Embedded FDE
      │  
[ WHAT WE BUILD ] — 5 capability sections with H3s
      │
[ BUSINESS IMPACT ] — measured/approved outcomes when available; otherwise describe expected mechanisms without pretending they are measured
      │
[ ENGAGEMENT PLAYBOOK ] — actual delivery stages; include timing only when approved and supportable
      │
[ OPTIONAL FAQ ] — include when user/search research supports it
      │
[ CTA ] — 'Book a 30-Minute FDE Technical Scope Session →'
```

### Template 3: Service Page (Individual Service)
Hierarchy:
```
[ HERO ] — Service name + what the client gets + primary CTA
      │
[ PROBLEM ] — What breaks without this service
      │
[ SOLUTION ] — How this service solves it (with architecture diagram)
      │
[ PROOF / METHOD ] — verified evidence when available; otherwise clearly labeled illustrative workflow(s) or transparent explanation of method
      │
[ TECHNICAL DEPTH ] — Stack, frameworks, architecture decisions
      │
[ PROCESS ] — How delivery works
      │
[ OPTIONAL FAQ ] — service-specific questions supported by user/search research
      │
[ CTA ] — Service-specific action
```

### Template 4: Blog Pillar Post
Hierarchy:
```
[ H1 ] — Primary keyword + benefit angle
      │
[ DIRECT ANSWER ] — concise, self-contained answer when supported by the observed query intent; length is topic-dependent
      │
[ MAIN SECTIONS ] — as many H2 sections as needed to solve the task with genuine depth
      │
[ COMPARISON ] — Table or matrix comparing approaches/tools
      │
[ USE CASES ] — relevant real examples with evidence, or clearly labeled illustrative scenarios
      │
[ OPTIONAL FAQ ] — include real user/PAA questions only when useful and verified; do not invent PAA observations
      │
[ INTERNAL CTA ] — Link to a relevant next step only when it fits reader intent
```
